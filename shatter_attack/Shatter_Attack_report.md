## Слайд 3. Определение Shatter Attack

- Действие: Дано определение атаки Shatter Attack
- Указано, что Shatter Attack:
  - относится к операционным системам семейства Windows
  - была впервые описана в 2002 году Крисом Пагетом
  - использует взаимодействие между процессами через оконные сообщения
  - позволяет процессу с низкими привилегиями отправлять команды окну процесса с высокими привилегиями

Результат: Показано, что атака основана не на прямом взломе пароля, а на использовании легитимного механизма Windows.

## Слайд 4. Механизм работы Windows Messaging

- Действие: Объяснён принцип работы механизма Windows Messaging
- В слайд включено описание, что GUI в Windows работает на основе очереди сообщений:

```text
Окно приложения (процесс A)
    ↓ SendMessage
Окно приложения (процесс B)
```

- Указаны примеры сообщений:
  - `WM_COMMAND`
  - `WM_TIMER`
  - `WM_USER`

- Описана структура сообщения:
  - `HWND` — идентификатор окна-получателя
  - ID сообщения
  - `wParam` — первый параметр
  - `lParam` — второй параметр

Результат: Показано, через какой системный механизм происходило взаимодействие между процессами.

## Слайд 5. Суть уязвимости

- Действие: Объяснено, почему Shatter Attack была возможна
- В слайд вынесены основные причины:
  - в Windows XP/2000 и более старых версиях сообщения не проверялись по источнику
  - любой процесс мог отправить сообщение любому окну
  - привилегированный процесс мог обработать сообщение от низкопривилегированного процесса
  - злоумышленник мог подставить вредоносные параметры

- Пример уязвимого вызова:

```cpp
SendMessage(hwnd, WM_COMMAND, ID_EXECUTE, (LPARAM)"cmd.exe");
```

Результат: Продемонстрирована ключевая проблема — отсутствие достаточной проверки источника межпроцессных сообщений.

## Слайд 9. Современное состояние

- Действие: Описана актуальность атаки в современных условиях
- В слайд вынесены выводы:
  - в современных Windows атака в классическом виде невозможна из-за UIPI
  - UIPI блокирует опасные сообщения от процессов с низким уровнем к процессам с высоким уровнем
  - атака остаётся важной для изучения старых систем и истории информационной безопасности

- Отдельно отмечено, что тема может быть актуальна для:
  - Windows XP/2000
  - Windows Embedded
  - анализа устаревших систем
  - изучения архитектурных ошибок в ОС

Результат: Показано, что Shatter Attack сегодня важна прежде всего как исторический и учебный пример.
